# T-010: send_sms_code 无发送频控，可被用于短信轰炸

## 元数据
- id: T-010
- severity: P2
- confidence: verified
- depends_on: none
- allowed_files:
  - services/api/app/config.py
  - services/api/app/services/auth_service.py
  - services/api/tests/test_auth.py
- allowed_extra_paths:
  - services/api/tests/test_auth_extra.py

## 问题描述
`POST /v1/auth/sms/send` 为公开端点，`auth_service.send_sms_code` 仅生成验证码落库并调用 provider，无任何按手机号/IP 的发送频率限制（已通读函数体确认；`sms_code_max_attempts` 只限制验证尝试次数）。切换真实短信供应商后，攻击者可对任意手机号循环触发付费短信（轰炸/骚扰），当前 mock 提供商下仅产生 SmsCode 表膨胀。

## 预期行为
- none（K12 产品短信接口的常规安全要求；与 E-003 未成年人保护的降噪目标一致）

## 定位锚点
- 文件: services/api/app/services/auth_service.py
- 符号: send_sms_code
- 锚点代码: `async def send_sms_code(session: AsyncSession, *, phone: str, purpose: str = "login") -> str:`
- 行号参考: 173

## 修复指令
1. 在 `services/api/app/config.py` 的 `Settings` 中 `sms_code_max_attempts: int = 5` 之后新增两行：`sms_send_interval_seconds: int = 60` 与 `sms_send_daily_limit: int = 10`。
2. 在 `services/api/app/services/auth_service.py` 的 `send_sms_code` 函数体开头（`code = _generate_code()` 之前）插入频控检查：查询 `select(func.count()).select_from(SmsCode).where(SmsCode.phone == phone, SmsCode.created_at >= utcnow() - timedelta(seconds=settings.sms_send_interval_seconds))`，结果 >0 时 `raise AuthError("发送过于频繁，请稍后再试", code="SMS_SEND_TOO_FREQUENT", status_code=429)`；再查询当日（`created_at >=当日零点`）计数，超过 `settings.sms_send_daily_limit` 时抛同 code 的 429。`func` 从 `sqlalchemy` 导入（文件头现有 `from sqlalchemy import delete, select, update` 中追加 `func`）。
3. 在 `tests/test_auth.py` 新增用例：同一手机号 60 秒内第二次调用 `/v1/auth/sms/send` 返回 429。
不得改动 `verify_sms_code` 的逻辑。
