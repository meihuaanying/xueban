# T-014: packages/core 错误契约 zod schema 不容 trace_id 为 null

## 元数据
- id: T-014
- severity: P2
- confidence: verified
- depends_on: none
- allowed_files:
  - packages/core/src/schemas.ts
- allowed_extra_paths: none

## 问题描述
后端统一错误契约 `_error_payload`（services/api/app/main.py:61-65）中 `trace_id` 来自 `_trace_id(request)`，可为 `None`，JSON 序列化为 `"trace_id": null`（main.py:63 `payload: dict[str, Any] = {"code": code, "message": message, "trace_id": trace_id}`）。共享契约 `packages/core/src/schemas.ts` 的 `ApiErrorSchema.trace_id` 仅 `z.string().optional()`，收到 `null` 即校验失败——比两端实际实现更窄（desktop 自身 api.ts:34 已声明 `trace_id?: string | null` 容纳 null）。任何消费 core 契约做响应校验的代码在 trace_id 为 null 的错误响应上会误报。

## 预期行为
- E-015（services/api/app/main.py `_error_payload`，代码显式契约）：错误体 {code, message, trace_id}，trace_id 可为 null。

## 定位锚点
- 文件: packages/core/src/schemas.ts
- 符号: ApiErrorSchema
- 锚点代码: `  trace_id: z.string().optional(),`
- 行号参考: 7

## 修复指令
在 `packages/core/src/schemas.ts` 的 `ApiErrorSchema` 中，将 `  trace_id: z.string().optional(),` 替换为 `  trace_id: z.string().nullable().optional(),`。不得改动该文件其他 schema。
