# T-011: /v1/library/docs 上传无大小与类型校验，任意字节全量读入内存

## 元数据
- id: T-011
- severity: P2
- confidence: verified
- depends_on: none
- allowed_files:
  - services/api/app/api/routes/tools.py
  - services/api/app/config.py
  - services/api/tests/test_library_cards.py
- allowed_extra_paths: none

## 问题描述
`upload_document` 处理函数执行 `data = await file.read()` 后直接交给解析入库，无大小上限、无 content-type/扩展名校验（文件名仅作为 DB 列记录）。对照同仓库 `storage_service.validate_upload`/`ALLOWED_UPLOADS`（presign 上传有类型与 `content-length-range` 白名单），该端点是唯一绕过这套校验的上传入口；Starlette 亦无默认请求体上限，超大文件将全量进入进程内存（内存耗尽型 DoS），非 PDF 字节也交由 pypdf 解析。

## 预期行为
- none（与 storage_service 的上传白名单约定保持一致；仓库内显式存在的上传校验契约）

## 定位锚点
- 文件: services/api/app/api/routes/tools.py
- 符号: upload_document
- 锚点代码: `    data = await file.read()`
- 行号参考: 87

## 修复指令
1. 在 `services/api/app/config.py` 的 `Settings` 中 `micro_lesson_max_chars: int = 1000` 之后新增一行：`library_upload_max_bytes: int = 20 * 1024 * 1024`。
2. 在 `services/api/app/api/routes/tools.py` 的 `upload_document` 中，将锚点 `    data = await file.read()` 替换为：
   `    data = await file.read()\n    if len(data) > settings.library_upload_max_bytes:\n        raise AppError("文件过大，最大 20MB", code="UPLOAD_TOO_LARGE", status_code=413)\n    if not (file.filename or "").lower().endswith(".pdf"):\n        raise AppError("仅支持 PDF 文档", code="UPLOAD_TYPE_INVALID", status_code=415)`
   （`settings` 已在本文件导入；`AppError` 从 `app.errors` 导入——若文件头未导入则追加）。
3. 在 `tests/test_library_cards.py` 新增用例：上传 >20MB 构造体返回 413；上传 .txt 文件名返回 415。
不得改动 `library_service.create_document` 的逻辑。
