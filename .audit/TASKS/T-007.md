# T-007: YidunProvider 请求缺签名且错误响应默认判"通过"，切换供应商后内容安全静默失效

## 元数据
- id: T-007
- severity: P1
- confidence: supported
- depends_on: none
- allowed_files:
  - services/api/app/services/safety_service.py
  - services/api/tests/test_safety.py
- allowed_extra_paths: none

## 问题描述
`YidunProvider.check` 仅发送 `secretId` 与 `content`，未携带易盾 v5 文本检测必需的签名参数（类 docstring 自述「签名按官方文档补齐」，未补）；且响应解析 `suggest = int(payload.get("result", {}).get("suggest", 0))` 在响应不含 `result`（易盾对未签名/错误请求返回 `{"code": <错误码>, "msg": ...}` 形态、HTTP 200）时默认取 0 = 通过。按 docs/COMPLIANCE.md §1.2 的指引配置 `YIDUN_SECRET_ID/KEY` 并切换 `SAFETY_PROVIDER=yidun` 后，所有请求都会被供应商以错误响应拒绝、而代码把每条内容判为 `allowed=True` 且 `provider="yidun"`（不走 fallback，无告警），未成年人内容过滤在表面上"已接入"实际全量放行。已核对 SafetyService.check 的兜底仅在抛 `SafetyProviderError` 时触发，当前实现不抛。

## 预期行为
- E-008（docs/COMPLIANCE.md §1.2）：`SAFETY_PROVIDER=mock|yidun` 可切换，失败降级本地词表不阻塞主流程——供应商不可用/拒绝时必须降级而非默认放行。

## 定位锚点
- 文件: services/api/app/services/safety_service.py
- 符号: YidunProvider.check
- 锚点代码: `suggest = int(payload.get("result", {}).get("suggest", 0))`
- 行号参考: 123（请求体锚点：`data={"secretId": self._settings.yidun_secret_id, "content": text},`，行号参考 116）

## 修复指令
在 `services/api/app/services/safety_service.py` 的 `YidunProvider.check` 内：
1. 将锚点 `suggest = int(payload.get("result", {}).get("suggest", 0))` 之前插入：
   `code = int(payload.get("code", 0))` 与
   `if code != 200:\n    raise SafetyProviderError(f"易盾接口错误：{payload.get('msg')}（code={code}）")`
   使签名缺失/供应商拒绝走 `SafetyProviderError` → SafetyService 触发本地词表兜底。
2. 按易盾 v5 文本检测官方文档为请求体补齐签名参数（signature/nonce/timestamp，算法以官方文档为准），将 `data={"secretId": ..., "content": text}` 替换为含签名参数的完整请求体。
3. 在 `tests/test_safety.py` 新增用例：mock 易盾返回 `{"code": 401, "msg": "signature error"}` 时，`SafetyService.check` 返回的 decision 的 `provider` 应为 `local-fallback`（即走了兜底），而非 `allowed=True, provider="yidun"`。
不得改动 `LocalWordProvider` 与 `SafetyService` 的兜底逻辑。
