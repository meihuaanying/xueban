# T-002: 判题沙箱前导码向用户代码泄露 `_REAL_IMPORT`，导入白名单可被绕过

## 元数据
- id: T-002
- severity: P1
- confidence: verified
- depends_on: none
- allowed_files:
  - services/api/app/services/judge_service.py
  - services/api/tests/test_judge.py
- allowed_extra_paths:
  - services/api/tests/test_grading.py

## 问题描述
`SANDBOX_PREAMBLE` 与用户代码写入同一个 `solution.py` 执行（run_python 内 `handle.write(SANDBOX_PREAMBLE.format(...))` 后紧跟 `handle.write(code)`），用户代码可直接引用前导码的模块级名字 `_REAL_IMPORT` 绕过 `_guarded_import` 的模块黑名单。已在本机（项目外临时目录）用当前仓库代码复现：提交 `m = _REAL_IMPORT("os")\nprint("OS_IMPORT_OK", len(m.listdir(".")) >= 0)` 后子进程正常执行并打印 `OS_IMPORT_OK True`（黑名单模块 `os` 导入成功）。剩余防线只有审计钩子 `_audit`（已实测其能拦截 C 层 `socket.__new__`，网络/越权文件读仍被拦），即声明的"隔离执行"退化为单层防御；`_ALLOWED_ROOTS`（含 Python 安装目录与 cwd）内的文件读取、任意目录 `os.listdir` 均放行。

## 预期行为
- E-016（services/api/app/services/judge_service.py 模块 docstring，代码显式契约）：「编程题判题沙箱（F-26）：隔离执行 + 资源/超时限制 + 评审式反馈」。

## 定位锚点
- 文件: services/api/app/services/judge_service.py
- 符号: SANDBOX_PREAMBLE / run_python
- 锚点代码: `_REAL_IMPORT = __import__`
- 行号参考: 49（SANDBOX_PREAMBLE 模板内）；run_python 拼接点 216-220

## 修复指令
在 `services/api/app/services/judge_service.py` 内：
1. 将 `SANDBOX_PREAMBLE` 中模块级定义的 `_ALLOWED_ROOTS`、`_BLOCKED_MODULES = {blocked!r}`、`_REAL_IMPORT = __import__`、`def _guarded_import(...)`、`def _audit(...)` 以及两行安装语句（`_sys.addaudithook(_audit)`、`__builtins__.__import__ = _guarded_import`）整体移入新函数 `def _xueban_install_guard():` 函数体内（`_guarded_import` 与 `_audit` 改为闭包引用 `_REAL_IMPORT` 与 `_ALLOWED_ROOTS`），preamble 末尾执行 `_xueban_install_guard()` 后紧跟 `del _xueban_install_guard`。
2. 在 `run_python` 中，将 `handle.write(code)`（锚点：`handle.write(SANDBOX_PREAMBLE.format(blocked=sorted(BLOCKED_MODULES))` 之后的两行写文件逻辑）替换为：把用户 `code` 写入同目录独立文件 `user_solution.py`，并在 `SANDBOX_PREAMBLE` 尾部（`del _xueban_install_guard` 之后）追加执行 `_sys.path.insert(0, _os.path.dirname(_os.path.abspath(__file__)))` 与 `import runpy as _r; _r.run_path("user_solution.py", run_name="__main__")`，使用户代码在独立模块命名空间执行、无法访问 preamble 模块级名字。
3. 在 `tests/test_judge.py` 新增用例：提交 `print(_REAL_IMPORT)` 应得到 `runtime_error`/`blocked`（NameError 路径），而非打印出函数对象。
不得修改 `_static_scan`、`FORBIDDEN_MARKERS`、`_limit_resources` 的现有逻辑。
