# T-009: WebSocket 鉴权未检查 is_active，且访问令牌经 URL query 传输落入访问日志

## 元数据
- id: T-009
- severity: P2
- confidence: verified
- depends_on: none
- allowed_files:
  - services/api/app/api/routes/sync.py
  - services/api/tests/test_sync.py
- allowed_extra_paths: none

## 问题描述
`_authenticate_ws` 解码 token 并按 `sub` 加载用户后直接返回，未检查 `user.is_active`（对照 `app/api/deps.py` 的 `get_current_user`，其对停用账号抛 `AUTH_ACCOUNT_DISABLED`）——已停用账号的存量 access token（≤15 分钟窗口内）仍可建立同步推送连接。同时 `sync_ws` 以 `token: str = Query(...)` 接收访问令牌：应用层 RequestLogMiddleware 只记 path 不含 query（已核对 middleware.py），但 uvicorn 默认 access log 与常见反向代理日志记录完整 query string，令牌会持久落入日志（与 E-011 日志脱敏红线相悖）。当前 apps/ 中尚无 `/v1/sync/ws` 客户端（已 grep desktop/mobile src 确认），改协议无兼容负担。

## 预期行为
- E-005（docs/COMPLIANCE.md §5）：访问控制——停用账号应被拒绝（与 get_current_user 行为一致）。
- E-011（docs/COMPLIANCE.md §2）：日志脱敏，敏感凭据不入 access 日志。

## 定位锚点
- 文件: services/api/app/api/routes/sync.py
- 符号: _authenticate_ws
- 锚点代码: `        user: User | None = await session.get(User, uuid.UUID(str(subject)))\n    return user`
- 行号参考: 65-66

## 修复指令
在 `services/api/app/api/routes/sync.py` 的 `_authenticate_ws` 内，将锚点中的 `return user` 替换为：
`    if user is None or not user.is_active:\n        return None\n    return user`
并将令牌传输从 query 迁移到首帧：`sync_ws` 的签名 `async def sync_ws(websocket: WebSocket, token: str = Query(...)) -> None:` 替换为 `async def sync_ws(websocket: WebSocket) -> None:`，函数体改为先 `await websocket.accept()`，再 `first = await asyncio.wait_for(websocket.receive_json(), timeout=5.0)`，从 `first.get("token")` 取令牌调用 `_authenticate_ws`；鉴权失败或超时 `await websocket.close(code=4401)` 并 return（保留原有推送循环不动）。在 `tests/test_sync.py` 更新/新增用例：停用用户连接被拒（4401）、首帧无 token 连接被拒。
