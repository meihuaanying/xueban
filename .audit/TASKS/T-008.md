# T-008: /v1/coach/scenes 为全部路由中唯一无认证的业务端点

## 元数据
- id: T-008
- severity: P2
- confidence: verified
- depends_on: none
- allowed_files:
  - services/api/app/api/routes/coach.py
  - services/api/tests/test_coach.py
- allowed_extra_paths: none

## 问题描述
`list_scenes` 返回预置陪练场景列表，处理函数无任何 `Depends(get_current_user)` / `require_roles` 参数，是 routes/ 23 个文件中唯一漏掉认证的业务端点（其余端点均有认证或属设计公开的 auth/billing/healthz/report-share）。信息敏感度低（仅场景标题/开场白），但破坏「业务端点一律认证」的仓库约定，且为未来扩展（若场景列表加入用户相关数据）埋下敞口。

## 预期行为
- none（仓库级约定：routes/ 其余全部业务端点均挂认证依赖；与 E-005 的服务端访问控制精神一致）

## 定位锚点
- 文件: services/api/app/api/routes/coach.py
- 符号: list_scenes
- 锚点代码: `async def list_scenes() -> list[dict[str, object]]:`
- 行号参考: 132

## 修复指令
在 `services/api/app/api/routes/coach.py` 的 `list_scenes` 中，将 `async def list_scenes() -> list[dict[str, object]]:` 替换为 `async def list_scenes(user: User = Depends(get_current_user)) -> list[dict[str, object]]:`（`get_current_user` 与 `User` 已在本文件头部导入）。函数体不变。在 `tests/test_coach.py` 新增用例：不带 Authorization 头请求 `POST /v1/coach/scenes` 应返回 401。

  - expected: all pass / exit 0
