# T-016: Tauri 主窗口 CSP 为 null，无任何内容安全策略

## 元数据
- id: T-016
- severity: P2
- confidence: supported
- depends_on: none
- allowed_files:
  - apps/desktop/src-tauri/tauri.conf.json
- allowed_extra_paths: none

## 问题描述
`apps/desktop/src-tauri/tauri.conf.json` 的 `security` 节为 `"csp": null`（无 csp、无 devCsp），主窗口 WebView 无任何内容安全策略。当前 UI 未发现 dangerouslySetInnerHTML 注入点（desktop src 全量检索仅 web 侧 2 处），讲解 HTML 由 sandbox iframe（无 allow-same-origin）承载，但一旦出现 XSS（第三方依赖投毒/未来内嵌富文本），注入脚本将无约束运行，且可通过 `invoke("credential_load")` 读取 OS keyring 中的 refresh token。capabilities 本身很窄（仅 `core:default` + 3 个自定义 keyring 命令），风险主要来自 csp 缺失与 keyring 读取命令的组合。

## 预期行为
- none（Tauri 官方安全基线要求显式设置 CSP；属平台最佳实践而非仓库内声明契约）

## 定位锚点
- 文件: apps/desktop/src-tauri/tauri.conf.json
- 符号: app.security
- 锚点代码: `"security": {\n      "csp": null\n    }`
- 行号参考: 23-25

## 修复指令
在 `apps/desktop/src-tauri/tauri.conf.json` 中，将锚点 `"security": {\n      "csp": null\n    }` 替换为：
`"security": {\n      "csp": "default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:; connect-src 'self' http://localhost:* http://127.0.0.1:* https://* http://* ws://localhost:* ws://127.0.0.1:*; frame-src 'self'"\n    }`
说明：`script-src 'unsafe-inline'` 是为讲解 iframe（srcdoc 注入的后端消毒 HTML 内联脚本）保留运行能力——srcdoc iframe 继承主窗口 CSP；`connect-src` 的宽 http/https 是因为 API_BASE_URL 支持运行时覆盖（localStorage `xueban.apiBaseUrl`），静态 CSP 无法穷举。若设置后桌面端 E2E（含讲解页用例）出现资源加载失败，按失败资源类别放宽对应 directive，不得回退为 null。不得改动该文件其他配置项。
