# T-015: 桌面端 keyring 不可用时 refresh token 以明文落入 localStorage

## 元数据
- id: T-015
- severity: P2
- confidence: verified
- depends_on: none
- allowed_files:
  - apps/desktop/src/lib/token-store.ts
  - apps/desktop/src/lib/token-store.test.ts
- allowed_extra_paths:
  - apps/desktop/src/lib/auth.tsx

## 问题描述
`saveSecret` 在 Tauri keyring 调用失败（`credential_save` 抛错）时回退 `window.localStorage.setItem(STORAGE_PREFIX + account, secret)`，`saveTokens` 对 access 与 refresh 两个令牌一视同仁。于是 30 天长效的 refresh token 在 keyring 不可用的机器上以明文 `xueban.desktop.refresh_token` 存于 localStorage：任何能读 localStorage 的脚本（XSS 或本机其他用户）即获得长期账户凭据。access token（15 分钟）回退 localStorage 的风险可接受，refresh token 不应回退。

## 预期行为
- E-005（docs/COMPLIANCE.md §5）：凭据保护——长效刷新令牌属敏感字段（对照 §2「敏感字段加密存储」精神）。

## 定位锚点
- 文件: apps/desktop/src/lib/token-store.ts
- 符号: saveSecret
- 锚点代码: `  window.localStorage.setItem(STORAGE_PREFIX + account, secret);`
- 行号参考: 27

## 修复指令
在 `apps/desktop/src/lib/token-store.ts` 中：
1. 将 `async function saveSecret(account: string, secret: string): Promise<void> {` 替换为 `async function saveSecret(account: string, secret: string, allowLocalFallback: boolean): Promise<void> {`，函数末尾回退分支 `  window.localStorage.setItem(STORAGE_PREFIX + account, secret);` 替换为 `  if (allowLocalFallback) {\n    window.localStorage.setItem(STORAGE_PREFIX + account, secret);\n  } else {\n    memorySecrets[account] = secret;\n  }`，并在文件顶部模块级新增 `const memorySecrets = new Map<string, string>();`。
2. `loadSecret` 的末尾 `  return window.localStorage.getItem(STORAGE_PREFIX + account);` 替换为 `  return window.localStorage.getItem(STORAGE_PREFIX + account) ?? memorySecrets.get(account) ?? null;`。
3. `deleteSecret` 中在 `window.localStorage.removeItem(...)` 之后追加 `  memorySecrets.delete(account);`。
4. `saveTokens` 中将 `  await saveSecret(REFRESH_ACCOUNT, pair.refresh_token);` 替换为 `  await saveSecret(REFRESH_ACCOUNT, pair.refresh_token, false);`，access 保持 `await saveSecret(ACCESS_ACCOUNT, pair.access_token, true);`。
5. 更新 `token-store.test.ts`：断言 keyring 失败时 `window.localStorage.getItem("xueban.desktop.refresh_token")` 为 null，且同会话内 `loadTokens()` 仍能取回 refresh token（内存路径）。
不得改动 keyring 调用与 `isTauri` 逻辑。
