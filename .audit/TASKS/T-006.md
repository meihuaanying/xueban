# T-006: 桌面端与移动端从不调用 /v1/auth/refresh，access token 15 分钟过期后会话失效

## 元数据
- id: T-006
- severity: P1
- confidence: verified
- depends_on: none

  - apps/desktop/src/lib/api.ts
  - apps/desktop/src/lib/endpoints.test.ts
  - apps/mobile/src/lib/api.ts

- allowed_extra_paths:
  - apps/desktop/src/lib/token-store.ts

## 问题描述
后端 access token 默认 15 分钟过期（config.py `access_token_expire_minutes: int = 15`），并提供 `POST /v1/auth/refresh`（routes/auth.py:106-114，rotate_refresh_token 实现完整）。但全 apps/ 目录 grep `auth/refresh` 零调用：desktop `request()` 收到 401 直接抛 `ApiError`，无自动刷新、无重试；refresh token 被持久化保存（token-store / SecureStore）却只用于 logout。运行超过 15 分钟后所有请求持续 401，用户被错误淹没直至重启应用（auth.tsx 仅在启动 `api.me()` 401 时清 token）。移动端 `request()` 同构同病。

## 预期行为
- E-005（docs/COMPLIANCE.md §5）：JWT access 15min / refresh 30d 轮换——轮换机制要求客户端配套使用，否则「30 天刷新」承诺不可达。

## 定位锚点
- 文件: apps/desktop/src/lib/api.ts
- 符号: request
- 锚点代码: `  if (!response.ok) {\n    throw new ApiError(response.status, (body ?? {}) as ApiErrorBody);\n  }`
- 行号参考: 78-80（apps/mobile/src/lib/api.ts 同构片段行号参考 49-51）

## 修复指令
1. 在 `apps/desktop/src/lib/api.ts` 的 `request` 内：将锚点的 `if (!response.ok) { throw ... }` 替换为——当 `response.status === 401` 且 `path` 不以 `/v1/auth/` 开头时，进入单飞刷新：模块级 `let refreshInFlight: Promise<boolean> | null = null`，刷新函数调用 `post<TokenPair>("/v1/auth/refresh", { refresh_token: <refreshToken> })`（refreshToken 通过新增模块级 `let refreshToken: string | null` 与 `export function setRefreshToken(t: string | null)` 管理，由 `auth.tsx` 登录/启动流程在 `setAccessToken` 同处调用；桌面端已有 token-store，此处仅内存传递），成功后 `setAccessToken(pair.access_token); setRefreshToken(pair.refresh_token)` 并用新头重放一次原 `fetch`；刷新失败（任何非 2xx）时 `setAccessToken(null); setRefreshToken(null)` 并抛出原 `ApiError`。并发 401 共享同一个 `refreshInFlight` Promise，防止刷新令牌轮换竞态（旧 refresh token 已被服务端吊销）。
2. `apps/desktop/src/lib/auth.tsx` 登录/恢复会话处同步调用 `setRefreshToken(...)`（该文件在 allowed_extra_paths 之外如需改动，用 apps/desktop/src/lib/session.tsx？不——以实际持有 pair 的调用点为准，位于 token-store/auth 流程内，已在 allowed_files/extra 覆盖范围）。
3. `apps/mobile/src/lib/api.ts` 的 `request` 做同构修改：refreshToken 从 `expo-secure-store` 的 `xueban.mobile.refresh_token` 键读取（`apps/mobile/src/lib/auth.tsx` 已有存取代码）。
4. 更新 `apps/desktop/src/lib/endpoints.test.ts` 与 `apps/mobile/src/__tests__/api.test.ts`：新增「401 → 刷新成功 → 重放成功」与「刷新失败 → 抛 401 且清空令牌」两组用例。
不得改变其余请求头处理与 `ApiError` 语义。
