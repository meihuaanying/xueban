## 问题描述
服务端唯一的防沉迷入口是 `GET /v1/guardian/status`（routes/parents.py:99-109 → parent_service.guardian_status），仅计算 `locked/reasons/used_minutes`，不产生任何拦截副作用；`main.py` 中间件只有 RequestLog/TraceId/CORS，全部学习类路由无一处引用 guardian_status。防沉迷锁定只由前端 `guardian-gate.tsx` 轮询锁屏实现，直接调用 API 即可绕过时长管控与宵禁。而 `parent_service.guardian_status` 的 docstring 自称「F-40：防本地篡改」，桌面端 `guardian-gate.tsx` 注释同样声称服务端判定不可本地绕过，与实际不符。本任务只新增依赖定义；路由挂载在 T-004。

## 修复指令
在 `services/api/app/api/deps.py` 的 `require_roles` 定义之后，新增依赖工厂（不改 `require_roles` 本体）：
`async def require_not_locked(user: User = Depends(get_current_user), session: AsyncSession = Depends(get_session)) -> User:`，函数体内 `from app.services import parent_service`，调用 `status = await parent_service.guardian_status(session, user=user)`；当 `status.locked` 为真时 `raise PermissionDeniedError("休息时间到，今天先到这里", code="GUARDIAN_LOCKED", status_code=423)`，否则 `return user`。导入保持文件既有 import 风格（`PermissionDeniedError` 已在文件头从 `app.errors` 导入）。在 `services/api/tests/test_guardian.py`（新文件，allowed_extra_paths 已列出）新增用例：构造已锁定用户（插入 study.time 埋点超过 daily_limit）后调用挂载该依赖的任一路由返回 423。
