## 问题描述
防沉迷锁定目前只在前端 `guardian-gate.tsx` 生效（见 T-003 问题描述）；本任务把 T-003 定义的 `require_not_locked` 依赖挂到全部学习类写/读端点，使锁定期间服务端直接拒绝（423 GUARDIAN_LOCKED），兑现「强制时长管控」红线。涉及端点：practice 的 generate/answer、tutor 的会话与提示族、exam 的创建/提交、diagnosis 的 start/answer、explainer 的 generate、review 的 due/grade、mistakes 的 repractice、coach 的对话回合。

## 修复指令
在 8 个 allowed_files 的每个路由处理函数参数列表中，追加一项 `user: User = Depends(require_not_locked)`（保留该函数原有的 `Depends(get_current_user)` 或 `require_roles(...)` 参数时，以 `require_not_locked` 替换 `get_current_user`——二者返回同一 `User`；`require_roles` 保留并额外追加 `Depends(require_not_locked)`），并在各文件头部 import 中加入 `require_not_locked`（来自 `app.api.deps`）。以 practice.py `generate` 为例：将参数中的 `user: User = Depends(get_current_user)` 替换为 `user: User = Depends(require_not_locked)`。不得改动任何端点的业务逻辑、路径与响应模型。若某端点原本无 `user` 参数（如 coach.py `list_scenes`，其认证问题由 T-008 处理），则跳过该端点，不在本任务为其加参。
