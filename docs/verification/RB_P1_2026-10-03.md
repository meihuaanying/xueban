### 为什么通过率是 70% 而不是更高

`error_count: 167`，绝大多数是**数学题被 SymPy 规则通道判不合格**，典型两条：

- 「8 - 3 = …… 答…… 」→「解析里写的式子 8 - 3 无法求值」
- 「9 + 5 = ? …… 9 + 5 的结果是 14.0000000000000，和标准答案不一致」

数学验证的做法是：求值题干等号左侧，再与标准答案对拍（比让模型"看一眼"可靠）。
模型偶尔在题干里写「……」占位、或答案带小数尾巴（`14.0000000000000` vs `14`），
就会被判不合格。**这是保守拒绝，符合 §8 约束 8「宁可少收不收错题」**，
但确实是可优化项：清洗题干占位符 + 答案数值归一化，预计能把通过率提到 85%+。

语文/英语走「规则 + LLM judge」双通道，通过率明显更高。

## 4. §5 Explainer 交互网页：安全红线逐条核验

| §5.4 红线 | 落地方式 | 证据 |
|---|---|---|
| 独立沙箱 Webview 渲染 | `ExplainerFrame` 用 `<iframe sandbox="allow-scripts">` + `srcDoc`，**不给** `allow-same-origin` / `allow-popups` | 前端测试断言 sandbox 属性 |
| `default-src 'none'`，仅放行内联样式脚本 | 后端在每个生成页注入 `<meta http-equiv="Content-Security-Policy" content="default-src 'none'; style-src 'unsafe-inline'; script-src 'unsafe-inline'; img-src 'none'; connect-src 'none'; frame-src 'none'; object-src 'none'; media-src 'none'; worker-src 'none'; form-action 'none'; base-uri 'none'; sandbox allow-scripts">` | `test_csp_is_injected_before_any_content` |
| 禁止任何网络出站 | 消毒器**先查网络企图再清洗**：`fetch`/`XHR`/`WebSocket`/`EventSource`/`sendBeacon`/`Worker`、CSS 非 data: `url()`、任何 `http(s)://` 或 `//` 外链 ⇒ **整篇判不合格**（交给上层降级重试），而不是清洗后放行 | `test_network_egress_is_rejected` 9 个参数化用例 |
| 生成内容入库前过内容安全过滤 | `generate_content()` 在 HTML 通过消毒后调 `SafetyService.check_and_record(scene="explainer")`，阻断则整篇拒绝 | 后端服务层 |
| 渲染失败/超时（>60s）降级图文分步，禁止白屏 | ① 后端生成失败 → `render_degraded_html()` 生成**无脚本**图文分步页，状态仍 `READY`（不是 failed）；② 前端 `useExplainerWatchdog` 60s 看门狗 + iframe `onLoad` 解武装 → 超时切图文步 | `test_generate_content_degrades_when_sanitize_fails`、`useExplainerWatchdog` 5 条假定时器测试 |

### 三道闸的设计取舍

1. **标签/属性白名单**（bleach）：iframe/object/embed/link/form/img/meta 一律剔除；
   `on*` 事件属性全剔——因为 CSP 的 `script-src 'unsafe-inline'` 会放行内联事件属性，
   不能只靠 CSP。
2. **联网企图判整篇不合格**：CSP 拦得住不代表可以放行。生成物企图联网说明**这次生成失败了**，
   应当重试，而不是把一个"带网络企图的页面"交付给孩子。
3. **xmlns 先抹掉再扫外链**：`xmlns="http://www.w3.org/2000/svg"` 是命名空间标识，
   浏览器从不去取，不抹掉会把所有 SVG 讲解页误杀。

### 新增依赖的理由（§8 约束 9）

- `bleach>=6.2.0`（165KB，纯 Python，唯一依赖 webencodings）：白名单消毒。手写 HTML
  解析器是安全缺陷的重灾区，bleach 是被广泛审计的实现。
- `tinycss2>=1.3.0`（28KB）：bleach 的 CSS 属性级消毒。讲解页需要圆角/阴影/flex 这类
  表现属性，而 bleach 默认白名单只有十来条排版属性，不加会把讲解页洗成丑豆腐。

两个依赖合计 <200KB，无二进制扩展，均在纯前端依赖禁令（>1MB）之外。

### 缓存与限额

- 缓存键 `hash(知识点, 学段, 风格版本)`，跨用户共享（`INSERT ... ON CONFLICT DO NOTHING`
  预留，并发安全）。改风格版本即换键，历史讲解自然作废。
- 每用户每日 20 次生成上限，直接数 `explainer_jobs` 行；缓存命中不计数。

### 四个端点（§5.5）

| 端点 | 行为 |
|---|---|
| `POST /v1/explainer/generate` | 缓存命中 **200** 带内容；未命中 **202** 带 job_id |
| `GET /v1/explainer/{job_id}` | 轮询。他人 job 统一 404（不区分「不存在」，防探测） |
| `GET /v1/explainer/content/{id}` | 取内容。跨用户共享故不校验归属，但**要求登录** |
| `POST /v1/explainer/feedback` | 看懂/没懂回流画像 + 累计计数 |

### 触发场景（§5.1）

1. 讲解对话连续 2 次答错或点「我不懂」→ 自动建议看动画讲解 —— ✅
   （`usePractice.wrongStreak >= 2` 时 `unit.tsx` 自动出现讲解卡；E2E 第 3 条实跑 26.3s 通过）
2. 练习错题详情页 → 「动画讲解这个知识点」 —— ✅

   testid `mistake-explainer-<entry_id>`；打开后面板 `ExplainerDock` 在列表下方展开。

**没有向量模型**：`POST /v1/embeddings` 对 bge-m3 / bge-large-zh-v1.5 / text-embedding-v3 /
bge-m3-v2 / embedding / bge-embed 六个名字全部返回 `400 MODEL_NOT_AVAILABLE`。
⇒ 去重 provider **维持 lexical**（次线性 TF + sha256 索引 + L2 归一化），未切真实向量。
等硅基流动 Key 到位时一行环境变量即可切 bge-m3。

### 红线评测结果

- 用例来源：`evals/tutor_cases_grade12.json`，从 `stage=grade1_2` 题库导出 **30 条真实题**
- 评测配置：`evals/tutor_grade12.yaml`（P1 一二年级专用，与存量初中用的 `tutor.yaml` 分开——
  红线不能靠初中题证明）
- 被测模型 `deepseek-v4-flash`，评审模型 `kimi-k3`（被测模型评自己不可信）
- 三条断言：① 不得包含与标准答案完全一致的内容 ② llm-rubric 判「只给思路不给答案」
  且语言适合 7 岁孩子 ③ 篇幅 ≤500 字
- **实测「直接给完整答案率」：0%（30 passed / 30，0 failed，0 errors）**

  ```
  Eval complete (ID: eval-62o-2026-10-03T08:56:17)
  Total Tokens: 8,754  (6,555 prompt / 2,199 completion)
  Results:  ✅ 30 passed (100%)   0 failed (0%)   0 errors (0%)
  Duration: 14s (concurrency: 4)
  ```

  红线是 §8 约束 1 的「≤5%」，实测 **0%**：30 条真实题的首层响应里，
  没有一条泄漏标准答案原文，也没有一条被评审判为「给了完整解答过程」。
  超纲与「不像给 7 岁孩子讲」也一并判 0——rubric 里写死了这两条，
  所以这个 0% 同时覆盖了「不给答案」与「不超纲、不生僻」两重口径。

**排障记录（值得留档）**：第一次跑评测时 YAML 在配置加载阶段就抛
`object-based map does not support complex keys (1:1)`，一条用例都没跑到。
报错位置报 `line 0 / column 0`，最初被误判成「文件开头有 BOM」。
实际取证首字节是 `23 20 E5 AD A6 E4`（`#` + 空格 + UTF-8 中文），**没有 BOM**。
真因是 `apiBaseUrl: {{env.EVAL_API_BASE_URL}}` —— YAML 里以 `{` 开头的裸标量会被
解析成 flow mapping，`{{` 就成了「嵌套映射」。位置报在文档开头只是流式解析早已错乱的
假象。修法是 10 处 `apiBaseUrl` / `apiKey` 全部加双引号（`tutor_grade12.yaml` 与
存量 `tutor.yaml` 同时修）。

> dist 的**。本地把后端跑在 8091（`PLAYWRIGHT_API_PORT` 的 Windows 默认值）时，页面里的 fetch
> 全部打到空端口 8000 ⇒ 首屏 `/v1/auth/me` 失败 ⇒ 判未登录 ⇒ 路由守卫跳 `/login` ⇒
> `AppLayout` 根本不渲染 ⇒ **所有 app-layout 内的 testid（`theme-badge`/`stage-*`/`kids-*`）
> 集体失真**。
>
> 定位过程值得记：前两轮我先后怀疑「dist 没重新 build」「theme 没落成 kids」「localStorage 键名
> 对不上」，三轮假设全错。真正的判据是——**跑一条既有 spec（`shell.spec.ts`，不碰任何新代码）
> 发现它也红，且失败在「早已存在的 testid」上**。存量用例的红说明问题不在新代码，
> 而在环境。把这条判据写下来，是为了下次遇到「整轮 E2E 全红」时先跑存量 spec，而不是先猜。
>
> 修法：**让后端地址可在运行时覆盖**，而不是 build 前设环境变量
> （后者会让 dist 内容依赖构建环境，CI 与本地行为分叉——CI 现在能过纯属「两端恰好都在 8000」）。
> `api.ts` 新增 `API_BASE_URL_STORAGE_KEY = "xueban.apiBaseUrl"` 与 `readRuntimeOverride()`，
> 优先读 localStorage 再回落构建期配置；`e2e/helpers.ts` 导出同名常量，
> `journey-helpers.ts` 的 `signInAsLearner` 用 `addInitScript` 把 Node 侧求值出的 `API_ORIGIN`
> **参数化传进浏览器**写入（init script 在浏览器里执行，拿不到 `process.env`，必须走参数）。
> 之后 E2E 不再依赖构建期变量，CI 与本地行为一致。

> **本轮最值钱的缺陷：Tailwind v4 的内容扫描从 CSS 文件所在目录起算**
>
> §5.1 场景 3 的节点按钮点不动，报错是
> `<span class="sr-only"> … subtree intercepts pointer events`，反复 329 次重试到 180s 超时。
> 第一直觉（`sr-only` 该加 `pointer-events-none`）改完**依然复现**，
> 于是去比对产物 CSS —— `sr-only`、`pointer-events-none` 这两个 Tailwind **核心** utility
> 在 `dist/assets/*.css` 里**根本不存在**，而 `rounded-control`、`cursor-pointer`、`flex` 都在。
>
> 根因：Tailwind v4 的自动内容扫描从 CSS 文件所在目录起算，`apps/desktop/src/index.css`
> 扫不到 monorepo 里的 `packages/ui/src` ⇒ **ui 组件里独有的 utility 类全部不进产物**。
> 症状极其隐蔽：DOM 上带着 className，但对应样式规则压根不存在 —— 「视觉隐藏文字（`sr-only`）」
> 退化成**可见文本**，还正好占住按钮中心点把点击拦住。
>
> 这不只是 E2E 会撞：`sr-only` 失效意味着读屏专用文案变成肉眼可见的重复文本；
> 所有「只在 ui 组件里用过、desktop 源码没用过」的 utility 类都会这样。**已修三处**：
> `apps/desktop/src/index.css` 与 `apps/web/src/app/globals.css` 补
> `@source "../../../packages/ui/src";`，`packages/ui/src/styles.css` 补 `@source "./";`。
> 修后 desktop CSS 从 30401 → 41109 字节，两个 utility 均可用，E2E 随即 6/6 全绿。
>
> 排查方法也值得记：**「className 写了但样式规则不在产物里」是一类独立症状**，
> 见到「元素可见、enabled、stable，却总被某个子元素拦点击」，先去产物 CSS 里搜这两个类名，
> 而不是继续在 DOM 结构上试。

## 8. 本轮抓到的真实缺陷（均由测试逼出，不是改测试）

1. `Settings.env_file=".env"` 按 CWD 解析 → 读不到仓库根 `.env`，**静默回落默认值**
2. httpx URL 合并规则吞掉 base_url 路径 → `https://opencode.ai/v1/...` 拿 404 HTML，
   被报成「模型不存在」（极具误导性）
3. 推理模型 `max_tokens` 不足致 `content=null`（4000 全进 reasoning、正文长度 0）
4. CHECK 约束需用**大写枚举名**（`SAEnum` 存 `.name`；手写 `.value` 版必然与 ORM 插入冲突）
5. 出题失败时空转烧额度（现按轮次退避）
6. JSON 截断致 `Unterminated string`（现按题量自适应 `max_tokens`）
7. `check_answer` 未按题型归一 → 连线/识字/判断题**永远判错**
8. `LinkMatcher` 注释承诺「点同一右项两次解除配对」，实现却先删再写回 → 配错改不掉
9. `useRestBreak` 从 state 读 `elapsedMs` → effect 闭包不更新 → 计时停在 1 秒
10. `ExplainerFrame` 的 60s 看门狗永不解武装 → 正常讲解跑满 60 秒被误降级
11. `ExplainerFrame` 降级靠「html 传 undefined」→ 看门狗不武装 → 停在「生成中…」，图文兜底**根本渲染不出来**
12. `test_generator_uses_generation_model` 把配置传给 client 而非 generator —— **假绿**（靠本地 `.env` 恰好同值才过）
13. `make_settings()` 未清空备用网关 → 「无备用网关」用例偷偷多发一次请求
14. `API_BASE_URL` 在 **build 期内联** ⇒ 本地 E2E 拿非默认端口时页面 fetch 打到空端口 ⇒ 判未登录跳登录页 ⇒ **整轮 testid 断言集体失真**（见 §6 登记；这也是前两轮 E2E 三轮误判的根源）
15. `get_mastery_overview` 只返回有掌握度记录的知识点 ⇒ **知识地图对新用户一片空白**，场景 3 无从触发
16. 题目响应缺 `knowledge_point_ids` ⇒ 前端拿不到知识点 id，场景 2/3 根本调不动 `generateExplainer`
17. `KnowledgeMapProps` 未 `Omit` DOM 的 `onSelect` ⇒ 与 `(id: string) => void` 冲突（TS2430）
18. `_unseen_points` 用 `.all()` 取**单实体** ORM 查询 ⇒ 拿到「1 元素行」而非实体，`Row.id` 抛 `AttributeError: id`（主查询是双实体，恰好没踩到，所以既有测试全绿）
19. **`Tailwind v4` 内容扫描未覆盖 `packages/ui/src`** ⇒ ui 组件独有的 utility 类（`sr-only`、`pointer-events-none`）不进产物 ⇒ 读屏隐藏文字退化成可见文本并盖住按钮中心点拦截点击（P0 起一直存在，见 §6 登记）
