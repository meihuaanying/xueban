## 3. 关键实现与决策

1. **登录态系统 keyring**：`apps/desktop/src-tauri/src/lib.rs` 暴露 `credential_save/load/delete`（`keyring` crate，按平台启用 windows-native / apple-native / secret-service）；前端 `token-store.ts` 在 Tauri 环境优先 keyring、失败或浏览器环境回退 localStorage（E2E 用 localStorage）。
2. **E2E 与构建口径**：E2E 基于 `vite preview` 的**生产构建**（与桌面安装包同一产物）；本机 API 固定 8091（8000 被系统保留段占用、8080 被既有工具占用），CI 用 8000。
3. **LLM mock provider**（后端）：新增 `LLM_PROVIDER=mock`（默认仍 litellm），按当前请求层级返回确定性讲解文本（只扫描 user 消息，避免被系统提示词中的「第 3 层」干扰）；E2E/CI 无 Key 亦能验证 SSE 与三层状态机真实链路，并新增 2 个单测。
4. **CORS 扩展**：允许 `http://127.0.0.1:4173`（Vite 预览）与 Tauri WebView 来源（`http://tauri.localhost`、`tauri://localhost`）。
5. **共享组件增强**：`Tabs` 增加可选 `onChange`（保持向后兼容，新增 1 个单测）；登录页区分登录/注册模式。
6. **打包**：NSIS（本机缓存工具链）；msi（WiX 需在线下载）与 mac/Linux 目标交由 CI；`tauri icon` 由品牌底 + 「学」字生成全平台图标。
7. **稳定性**：E2E 本地 workers=4、retries=1；诊断用例最后一题直接断言报告（消除反馈渲染竞态）。
