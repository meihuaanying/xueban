## 3. 实测链路证据

### 3.1 Langfuse trace（T1.5）

```
TRACE_FOUND id=bfce1eaf76e840378611336b9ccdef55 name=llm.connectivity_check
  - observation: tutor.hint.level1 type=GENERATION level=DEFAULT model=deepseek-chat
  - observation: llm.connectivity_check type=GENERATION level=ERROR model=deepseek-chat
VERIFY_OK
```

说明：`tutor.hint.level1` 为「守护型讲解首层提示」形态的成功 trace（含 prompt/输出/token/耗时）；
`llm.connectivity_check` 为经 LiteLLM 的真实调用（当前无供应商 Key，故以 ERROR 级留痕并返回明确错误）。Langfuse UI：http://localhost:3100（开发密钥 pk/sk-lf-xueban-dev）。

### 3.2 LiteLLM fallback 链（T1.4）

实测响应（节选）：主模型 `deepseek-chat` 因未配置供应商 Key 失败后，自动尝试 `qwen-plus`、`glm-4`，
最终返回结构化错误且包含 `Available Model Group Fallbacks=['qwen-plus', 'glm-4']` —— 证明 fallback 链已生效。
应用层将其映射为 `LLM_AUTH_FAILED`（503），携带供应商原始错误信息，不崩溃。

### 3.3 活体冒烟（T1.8）

真实 uvicorn 进程：`/healthz` 200、`/docs` 200、注册 201、`/v1/auth/me` 200、订阅状态 `free`、响应含 `X-Trace-Id`。

## 5. 关键设计决策

| # | 决策 | 说明 |
|---|------|------|
| 1 | 测试库独立（`xueban_test`） | 会话级自动建库 + Alembic 迁移 + 用例后 TRUNCATE；引擎 NullPool 规避跨事件循环 |
| 2 | 刷新令牌入库存摘要 + 轮换吊销 | 旧令牌复用返回 `AUTH_TOKEN_REVOKED`，防重放 |
| 3 | 验证码失败计数持久化 | 失败路径显式 commit，保证 5 次上限真实生效（429） |
| 4 | MinIO 预签名 POST + `content-length-range` | 服务端强制大小限制（不信任客户端声明） |
| 5 | 内容安全「远程优先 + 本地兜底」 | 远程异常自动回退词表且标记 `local-fallback`，拦截事件入库 |
| 6 | Langfuse 观测永不阻塞主流程 | 所有 SDK 调用包异常捕获；未配置密钥时为空实现 |
| 7 | Langfuse 开发环境自动初始化项目 | compose `LANGFUSE_INIT_*`（仅开发；生产走 UI 创建） |
