**根因与优化记录**（详见 B-017）：

- 已落地：中间件 BaseHTTPMiddleware → **纯 ASGI**（单请求 CPU 约 -30%）；连接池可配置（`DB_POOL_*`）；PG `max_connections=200`；关闭 `pool_pre_ping` 省一次往返；Caddy `lb_policy round_robin`；容器内网直连 PG。
- 实测瓶颈：应用 CPU 密集（约 11ms CPU/请求；SQLAlchemy/asyncpg 协议栈 + 事件循环回调为主要成本），扩张到 16 worker 后吞吐不再上升，**本机共享算力上限约 900 rps**；k6 压测器、PG、Caddy 与 13 个开发容器同机竞争。
- 复测路径：T11.1 生产栈部署至独立 VPS（≥16 专用 vCPU）后原样执行 `infra/k6/core_api.js` 回填。
