### 4.1 队列实测暴露并修复的健壮性缺陷

题库队列续跑后，真实模型输出又暴露三个会让「整个知识点」失败的缺陷，均已修复并加回归用例：

| 缺陷 | 现象 | 修复 |
|---|---|---|
| SymPy 括号不配对 | 模型输出 `1))` / `((1+2)`，SymPy 抛 `IndexError` / `tokenize.TokenError`，`parse_math` 未捕获，整点失败 | `math_verify.parse_math` 捕获 `IndexError`/`TokenError`，退化为「不可解析」；`test_parse_math_unbalanced_parentheses_do_not_raise` |
| 连续 JSON 对象 | 模型输出 `{...}\n{...}`，贪婪截取报 `Extra data` | `llm_json` 用 `raw_decode` 取第一个完整对象；顺带修复代码围栏嵌套对象的非贪婪截断；3 条用例 |
| LaTeX 反斜杠未转义 | `\sqrt` / `\alpha` 直接写进 JSON 字符串，报 `Invalid \escape` | 解析失败后补转义重试（`strict=False` 兼容字符串内真实换行）；`test_extract_json_object_repairs_unescaped_latex` 等 |
| 出题器绕过宽松解析 | `question_generator._extract_questions` 自己调 `json.loads`，LaTeX 转义错误仍让整点失败 | 抽出共享 `parse_json_value`（对象/数组通用），出题器改用它；数组 + 截断用例 |
| 小学阅读题干被长度上限误拒 | 阅读理解题干含短文（350~400 字），小学 300 字上限导致 `g5e-reading-passage` 等 0 题 | 阅读类小学知识点放宽到 600 字；`test_rule_verify_allows_passage_stem_for_primary_reading` |
| SymPy 逗号表达式崩溃 | `1,2` 被解析成 tuple，`_check_math_answer` 调 `.evalf()` 抛 `AttributeError`，整点 0 题 | 非 `sympy.Expr` 结果交给 judge；`test_rule_verify_defers_tuple_math_to_judge` |

效果：以上修复后逐点补题，课程树内不足 30 题的知识点从 780（含大量非课程树旧数据）
降至 **0**；截至 2026-11-05 12:25，全库 **PUBLISHED 35935（较起点 +23996）**，REVIEW 1817。
